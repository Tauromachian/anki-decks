What does <code>Array.prototype.map()</code> do in JavaScript? Give an example.	Creates a <b>new array</b> by applying a function to every element. Does <b>not</b> mutate the original.<br><br><pre><code>const nums = [1, 2, 3];<br>const doubled = nums.map(n =&gt; n * 2);<br>// doubled: [2, 4, 6]<br>// nums: [1, 2, 3] (unchanged)</code></pre>
What does <code>Array.prototype.filter()</code> do in JavaScript? Give an example.	Creates a <b>new array</b> with only elements that pass a test (return <code>true</code>). Does <b>not</b> mutate the original.<br><br><pre><code>const nums = [1, 2, 3, 4];<br>const evens = nums.filter(n =&gt; n % 2 === 0);<br>// evens: [2, 4]</code></pre>
What does <code>Array.prototype.reduce()</code> do in JavaScript? Give an example.	Reduces an array to a <b>single value</b> by accumulating each element. Takes <code>(accumulator, currentValue)</code> and an initial value.<br><br><pre><code>const nums = [1, 2, 3, 4];<br>const sum = nums.reduce((acc, n) =&gt; acc + n, 0);<br>// sum: 10</code></pre>
What does <code>Array.prototype.at()</code> do? Give an example.	Returns the element at <code>index</code>. Negative index counts from the end. Does <b>not</b> mutate.<br><br><pre><code>const a = [10, 20, 30];<br>a.at(0); // 10<br>a.at(-1); // 30 (a[-1] would be undefined)</code></pre>
What does <code>Array.prototype.concat()</code> do? Give an example.	Merges arrays/values into a <b>new array</b>. Does <b>not</b> mutate.<br><br><pre><code>[1, 2].concat([3, 4], 5); // [1, 2, 3, 4, 5]</code></pre>
What does <code>Array.prototype.copyWithin()</code> do? Give an example.	Copies a slice of the array to another position <b>in the same array</b>. <b>Mutates</b>, returns same array.<br><br><pre><code>const a = [1, 2, 3, 4, 5];<br>a.copyWithin(0, 3); // [4, 5, 3, 4, 5]</code></pre>
What does <code>Array.prototype.entries()</code> do? Give an example.	Returns an iterator of <code>[index, value]</code> pairs. Does <b>not</b> mutate.<br><br><pre><code>for (const [i, v] of ['a','b'].entries()) console.log(i, v);<br>// 0 'a'<br>// 1 'b'</code></pre>
What does <code>Array.prototype.every()</code> do? Give an example.	Returns <code>true</code> if <b>all</b> elements pass the test, else <code>false</code>. Does <b>not</b> mutate.<br><br><pre><code>[2, 4, 6].every(n =&gt; n % 2 === 0); // true<br>[2, 3].every(n =&gt; n % 2 === 0); // false</code></pre>
What does <code>Array.prototype.fill()</code> do? Give an example.	Fills elements with a static value from <code>start</code> to <code>end</code> (end excluded). <b>Mutates</b>, returns same array.<br><br><pre><code>const a = [1, 2, 3];<br>a.fill(0, 1, 3); // [1, 0, 0]</code></pre>
What does <code>Array.prototype.find()</code> do? Give an example.	Returns the <b>first</b> element passing the test, else <code>undefined</code>. Does <b>not</b> mutate.<br><br><pre><code>[1, 2, 3].find(n =&gt; n &gt; 1); // 2</code></pre>
What does <code>Array.prototype.findIndex()</code> do? Give an example.	Returns the <b>index</b> of the first element passing the test, else <code>-1</code>. Does <b>not</b> mutate.<br><br><pre><code>[1, 2, 3].findIndex(n =&gt; n &gt; 1); // 1</code></pre>
What does <code>Array.prototype.findLast()</code> do? Give an example.	Like <code>find()</code> but from the <b>end</b>. Returns last passing element, else <code>undefined</code>. Does <b>not</b> mutate.<br><br><pre><code>[1, 2, 3, 4].findLast(n =&gt; n % 2 === 0); // 4</code></pre>
What does <code>Array.prototype.findLastIndex()</code> do? Give an example.	Like <code>findIndex()</code> but from the <b>end</b>. Returns index or <code>-1</code>. Does <b>not</b> mutate.<br><br><pre><code>[1, 2, 3, 4].findLastIndex(n =&gt; n % 2 === 0); // 3</code></pre>
What does <code>Array.prototype.flat()</code> do? Give an example.	Flattens nested arrays up to <code>depth</code> (default 1). Returns <b>new array</b>, removes empty slots.<br><br><pre><code>[1, [2, [3]]].flat(); // [1, 2, [3]]<br>[1, [2, [3]]].flat(2); // [1, 2, 3]</code></pre>
What does <code>Array.prototype.flatMap()</code> do? Give an example.	Maps each element then flattens 1 level. Equals <code>map().flat(1)</code> but more efficient. Returns <b>new array</b>.<br><br><pre><code>[1, 2, 3].flatMap(n =&gt; [n, n * 2]); // [1, 2, 2, 4, 3, 6]</code></pre>
What does <code>Array.prototype.forEach()</code> do? How is it different from <code>map()</code>?	Executes a function per element. Returns <code>undefined</code>. Cannot be chained, cannot <code>break</code>. Use for side effects; use <code>map()</code> to build a new array. Does <b>not</b> mutate by itself.<br><br><pre><code>['a','b'].forEach((v, i) =&gt; console.log(i, v));<br>// 0 'a'<br>// 1 'b'</code></pre>
What does <code>Array.prototype.includes()</code> do? Give an example.	Returns <code>true</code> if array contains the value (uses SameValueZero, finds <code>NaN</code>). Does <b>not</b> mutate.<br><br><pre><code>[1, 2, NaN].includes(NaN); // true<br>[1, 2].includes(2, 1); // true (fromIndex 1)</code></pre>
What does <code>Array.prototype.indexOf()</code> do? Give an example.	Returns <b>first index</b> of value (strict equality), else <code>-1</code>. Cannot find <code>NaN</code>. Does <b>not</b> mutate.<br><br><pre><code>['a','b','a'].indexOf('a'); // 0<br>['a','b'].indexOf('a', 1); // -1</code></pre>
What does <code>Array.prototype.join()</code> do? Give an example.	Joins all elements into a <b>string</b> with separator (default <code>','</code>). Does <b>not</b> mutate.<br><br><pre><code>['a','b','c'].join('-'); // 'a-b-c'<br>[1, 2].join(); // '1,2'</code></pre>
What does <code>Array.prototype.keys()</code> do? Give an example.	Returns an iterator of <b>indices</b>. Does <b>not</b> mutate.<br><br><pre><code>for (const k of ['a','b'].keys()) console.log(k);<br>// 0<br>// 1</code></pre>
What does <code>Array.prototype.lastIndexOf()</code> do? Give an example.	Returns <b>last index</b> of value searching backwards, else <code>-1</code>. Does <b>not</b> mutate.<br><br><pre><code>['a','b','a'].lastIndexOf('a'); // 2</code></pre>
What does <code>Array.prototype.pop()</code> do? Give an example.	Removes the <b>last</b> element. <b>Mutates</b>. Returns removed element (or <code>undefined</code> if empty).<br><br><pre><code>const a = [1, 2, 3];<br>a.pop(); // 3, a is now [1, 2]</code></pre>
What does <code>Array.prototype.push()</code> do? Give an example.	Adds items to the <b>end</b>. <b>Mutates</b>. Returns <b>new length</b>.<br><br><pre><code>const a = [1, 2];<br>a.push(3, 4); // 4, a is now [1, 2, 3, 4]</code></pre>
What does <code>Array.prototype.reduceRight()</code> do? Give an example.	Like <code>reduce()</code> but iterates <b>right-to-left</b>. Returns single value.<br><br><pre><code>[[0,1],[2,3]].reduceRight((a, b) =&gt; a.concat(b)); // [2, 3, 0, 1]</code></pre>
What does <code>Array.prototype.reverse()</code> do? Give an example.	Reverses order <b>in place</b>. <b>Mutates</b>, returns same array. For non-mutating use <code>toReversed()</code>.<br><br><pre><code>const a = [1, 2, 3];<br>a.reverse(); // [3, 2, 1]</code></pre>
What does <code>Array.prototype.shift()</code> do? Give an example.	Removes the <b>first</b> element. <b>Mutates</b>. Returns removed element.<br><br><pre><code>const a = [1, 2, 3];<br>a.shift(); // 1, a is now [2, 3]</code></pre>
What does <code>Array.prototype.slice()</code> do? Give an example.	Returns a shallow copy from <code>start</code> to <code>end</code> (end excluded). Negative = from end. Does <b>not</b> mutate.<br><br><pre><code>const a = [1, 2, 3, 4];<br>a.slice(1, 3); // [2, 3]<br>a.slice(-2); // [3, 4]</code></pre>
What does <code>Array.prototype.some()</code> do? Give an example.	Returns <code>true</code> if <b>at least one</b> element passes the test. Does <b>not</b> mutate.<br><br><pre><code>[1, 2, 3].some(n =&gt; n % 2 === 0); // true</code></pre>
What does <code>Array.prototype.sort()</code> do? Give an example.	Sorts <b>in place</b>. <b>Mutates</b>, returns same array. Default is lexicographic — always pass compare fn for numbers. For non-mutating use <code>toSorted()</code>.<br><br><pre><code>[10, 1, 2].sort(); // [1, 10, 2] (pitfall!)<br>[10, 1, 2].sort((a, b) =&gt; a - b); // [1, 2, 10]</code></pre>
What does <code>Array.prototype.splice()</code> do? Give an example.	Adds/removes elements at position. <b>Mutates</b>. Returns array of <b>deleted</b> elements. For non-mutating use <code>toSpliced()</code>.<br><br><pre><code>const a = [1, 2, 3, 4];<br>a.splice(1, 2, 'x'); // returns [2, 3], a is [1, 'x', 4]</code></pre>
What does <code>Array.prototype.toLocaleString()</code> do? Give an example.	Returns a locale-sensitive <b>string</b> of elements. Does <b>not</b> mutate.<br><br><pre><code>[1000, new Date()].toLocaleString('en-US'); // e.g. '1,000,9/8/2026, ...'</code></pre>
What does <code>Array.prototype.toReversed()</code> (ES2023) do? Give an example.	Non-mutating <code>reverse()</code>. Returns <b>new array</b>.<br><br><pre><code>const a = [1, 2, 3];<br>a.toReversed(); // [3, 2, 1], a unchanged</code></pre>
What does <code>Array.prototype.toSorted()</code> (ES2023) do? Give an example.	Non-mutating <code>sort()</code>. Returns <b>new array</b>.<br><br><pre><code>const a = [3, 1, 2];<br>a.toSorted((x, y) =&gt; x - y); // [1, 2, 3], a unchanged</code></pre>
What does <code>Array.prototype.toSpliced()</code> (ES2023) do? Give an example.	Non-mutating <code>splice()</code>. Returns <b>new array</b>.<br><br><pre><code>[1, 2, 3].toSpliced(1, 1, 'x'); // [1, 'x', 3]</code></pre>
What does <code>Array.prototype.toString()</code> do? Give an example.	Returns string of elements joined with <code>','</code>. Same as <code>join(',')</code>. Does <b>not</b> mutate.<br><br><pre><code>[1, 2, [3, 4]].toString(); // '1,2,3,4'</code></pre>
What does <code>Array.prototype.unshift()</code> do? Give an example.	Adds items to the <b>start</b>. <b>Mutates</b>. Returns <b>new length</b>.<br><br><pre><code>const a = [2, 3];<br>a.unshift(0, 1); // 4, a is now [0, 1, 2, 3]</code></pre>
What does <code>Array.prototype.values()</code> do? Give an example.	Returns an iterator of <b>values</b>. Same as iterating the array directly. Does <b>not</b> mutate.<br><br><pre><code>for (const v of ['a','b'].values()) console.log(v);</code></pre>
What does <code>Array.prototype.with()</code> (ES2023) do? Give an example.	Non-mutating set: returns <b>new array</b> with element at <code>index</code> replaced. Supports negative index.<br><br><pre><code>const a = [1, 2, 3];<br>a.with(1, 'x'); // [1, 'x', 3], a unchanged<br>a.with(-1, 'z'); // [1, 2, 'z']</code></pre>
What does <code>Array.from()</code> (static) do? Give an example.	Creates an array from an iterable or array-like, with optional map fn.<br><br><pre><code>Array.from('abc'); // ['a','b','c']<br>Array.from({length: 3}, (_, i) =&gt; i); // [0, 1, 2]</code></pre>
What does <code>Array.isArray()</code> (static) do? Give an example.	Returns <code>true</code> only if value is an Array. Prefer over <code>instanceof</code> (works cross-realm).<br><br><pre><code>Array.isArray([1, 2]); // true<br>Array.isArray('abc'); // false</code></pre>
What does <code>Array.of()</code> (static) do? Give an example.	Creates an array from arguments. Fixes <code>new Array(3)</code> pitfall (which makes empty slots).<br><br><pre><code>Array.of(3); // [3]<br>new Array(3); // [empty x 3]<br>Array.of(1, 2, 3); // [1, 2, 3]</code></pre>
What does <code>Array.fromAsync()</code> (static, ES2024) do? Give an example.	Async version of <code>from()</code>: creates array from async-iterable/promise values. Returns a <code>Promise</code>.<br><br><pre><code>await Array.fromAsync([Promise.resolve(1), 2]); // [1, 2]</code></pre>
What does <code>String.prototype.at()</code> do? Give an example.	Returns the character at <code>index</code>. Negative counts from the end. Returns <code>undefined</code> out of range. Strings are <b>immutable</b> — all string methods return a new string.<br><br><pre><code>'hello'.at(1); // 'e'<br>'hello'.at(-1); // 'o'</code></pre>
What does <code>String.prototype.charAt()</code> do? How is it different from <code>at()</code>?	Returns the character at <code>index</code>, or <code>''</code> out of range. Unlike <code>at()</code>, it does <b>not</b> support negative indices.<br><br><pre><code>'hello'.charAt(1); // 'e'<br>'hello'.charAt(-1); // '' (at(-1) would be 'o')</code></pre>
What does <code>String.prototype.charCodeAt()</code> do? Give an example.	Returns the UTF-16 code <b>unit</b> (0–65535) at <code>index</code>, or <code>NaN</code> out of range. Splits surrogate pairs (emoji = 2 units). For full code points use <code>codePointAt()</code>.<br><br><pre><code>'A'.charCodeAt(0); // 65<br>'😀'.charCodeAt(0); // 55357 (high surrogate only)</code></pre>
What does <code>String.prototype.codePointAt()</code> do? Give an example.	Returns the full Unicode <b>code point</b> at <code>index</code> (handles astral chars/emoji as one). Returns <code>undefined</code> out of range.<br><br><pre><code>'😀'.codePointAt(0); // 128512<br>'😀'.codePointAt(0).toString(16); // '1f600'</code></pre>
What does <code>String.prototype.concat()</code> do? Give an example.	Joins strings into a <b>new string</b>. Equivalent to <code>+</code>, rarely needed.<br><br><pre><code>'a'.concat('b', 'c'); // 'abc'<br>// same as 'a' + 'b' + 'c'</code></pre>
What does <code>String.prototype.endsWith()</code> do? Give an example.	Returns <code>true</code> if the string ends with the search string. Optional 2nd arg = length to consider as end.<br><br><pre><code>'hello'.endsWith('lo'); // true<br>'hello'.endsWith('l', 3); // true ('hel' ends with 'l')</code></pre>
What does <code>String.prototype.includes()</code> do? Give an example.	Returns <code>true</code> if the substring is found (case-sensitive). Optional 2nd arg = start position.<br><br><pre><code>'hello'.includes('ell'); // true<br>'hello'.includes('ELL'); // false<br>'hello'.includes('l', 3); // true</code></pre>
What does <code>String.prototype.indexOf()</code> do? Give an example.	Returns the <b>first index</b> of the substring, else <code>-1</code>. Optional 2nd arg = from index. Case-sensitive.<br><br><pre><code>'hello'.indexOf('l'); // 2<br>'hello'.indexOf('l', 3); // 3<br>'hello'.indexOf('z'); // -1</code></pre>
What does <code>String.prototype.isWellFormed()</code> (ES2024) do? Give an example.	Returns <code>false</code> if the string contains <b>lone surrogates</b> (invalid UTF-16), else <code>true</code>. Pair with <code>toWellFormed()</code>.<br><br><pre><code>'hi'.isWellFormed(); // true<br>'\uD800'.isWellFormed(); // false (lone surrogate)</code></pre>
What does <code>String.prototype.lastIndexOf()</code> do? Give an example.	Like <code>indexOf()</code> but searches <b>backwards</b>. Returns last index or <code>-1</code>.<br><br><pre><code>'hello'.lastIndexOf('l'); // 3<br>'hello'.lastIndexOf('l', 2); // 2</code></pre>
What does <code>String.prototype.localeCompare()</code> do? Give an example.	Compares strings per locale for sorting. Returns negative / <code>0</code> / positive (not just -1/0/1).<br><br><pre><code>'a'.localeCompare('b'); // negative<br>['ä','z'].sort((x, y) =&gt; x.localeCompare(y, 'de'));</code></pre>
What does <code>String.prototype.match()</code> do? Give an example.	Matches against a regex/string. Without <code>/g</code> returns match object with groups; with <code>/g</code> returns array of matches (no groups). Returns <code>null</code> if none.<br><br><pre><code>'abc123'.match(/\d+/); // ['123', ...] with index<br>'a1b2'.match(/\d/g); // ['1', '2']</code></pre>
What does <code>String.prototype.matchAll()</code> do? Give an example.	Returns an <b>iterator</b> of all matches with groups. Regex must have <code>/g</code> flag.<br><br><pre><code>for (const m of 'a1b2'.matchAll(/\d/g)) console.log(m[0]); // '1', '2'</code></pre>
What does <code>String.prototype.normalize()</code> do? Give an example.	Returns Unicode-normalized form: <code>NFC</code> (default), <code>NFD</code>, <code>NFKC</code>, <code>NFKD</code>. Needed to compare accented chars with different encodings.<br><br><pre><code>'é'.length; // 1 or 2 depending on form<br>'\u00e9' === '\u0065\u0301'; // false<br>'\u00e9' === '\u0065\u0301'.normalize(); // true (NFC)</code></pre>
What does <code>String.prototype.padEnd()</code> do? Give an example.	Pads the <b>end</b> to reach <code>targetLength</code> with <code>padString</code> (default space). Returns <b>new string</b>.<br><br><pre><code>'5'.padEnd(3, '0'); // '500'<br>'hi'.padEnd(5); // 'hi   '</code></pre>
What does <code>String.prototype.padStart()</code> do? Give an example.	Pads the <b>start</b> to reach <code>targetLength</code>. Common for clocks/IDs.<br><br><pre><code>'5'.padStart(2, '0'); // '05'<br>'hi'.padStart(5); // '   hi'</code></pre>
What does <code>String.prototype.repeat()</code> do? Give an example.	Returns the string repeated <code>count</code> times. Throws <code>RangeError</code> on negative or infinite count.<br><br><pre><code>'ab'.repeat(3); // 'ababab'<br>'-'.repeat(0); // ''</code></pre>
What does <code>String.prototype.replace()</code> do? Give an example.	Replaces the <b>first</b> match (string or regex without <code>/g</code>) with a string or replacer function. Supports <code>$&amp;</code>, <code>$1</code> patterns.<br><br><pre><code>'aaa'.replace('a', 'b'); // 'baa'<br>'aaa'.replace(/a/g, 'b'); // 'bbb'<br>'hi'.replace(/(\w+)/, '&lt;$1&gt;'); // '&lt;hi&gt;'</code></pre>
What does <code>String.prototype.replaceAll()</code> do? Give an example.	Replaces <b>all</b> matches. A regex must have <code>/g</code>, else it throws.<br><br><pre><code>'aaa'.replaceAll('a', 'b'); // 'bbb'<br>'aaa'.replaceAll(/a/g, 'b'); // 'bbb'</code></pre>
What does <code>String.prototype.search()</code> do? Give an example.	Returns the index of the <b>first regex match</b>, else <code>-1</code>. Takes a regex (string is converted). Like <code>indexOf()</code> but for regex.<br><br><pre><code>'abc123'.search(/\d/); // 3<br>'abc'.search(/\d/); // -1</code></pre>
What does <code>String.prototype.slice()</code> do? Give an example.	Extracts from <code>start</code> to <code>end</code> (end excluded) into a <b>new string</b>. Negative = from end.<br><br><pre><code>'hello'.slice(1, 3); // 'el'<br>'hello'.slice(-2); // 'lo'<br>'hello'.slice(1); // 'ello'</code></pre>
What does <code>String.prototype.split()</code> do? Give an example.	Splits into an <b>array</b> by separator (string or regex). Optional 2nd arg = limit. Empty string splits into chars.<br><br><pre><code>'a,b,c'.split(','); // ['a','b','c']<br>'abc'.split(''); // ['a','b','c']<br>'a1b2'.split(/\d/); // ['a','b','']</code></pre>
What does <code>String.prototype.startsWith()</code> do? Give an example.	Returns <code>true</code> if the string starts with the search string. Optional 2nd arg = start position.<br><br><pre><code>'hello'.startsWith('he'); // true<br>'hello'.startsWith('llo', 2); // true</code></pre>
What is the difference between <code>slice()</code> and <code>substring()</code>?	<code>slice()</code> supports negatives (from end); <code>substring()</code> treats negatives as <code>0</code> and <b>swaps</b> args if start &gt; end. Prefer <code>slice()</code>.<br><br><pre><code>'hello'.slice(3, 1); // ''<br>'hello'.substring(3, 1); // 'el' (swapped to 1,3)<br>'hello'.slice(-2); // 'lo'<br>'hello'.substring(-2); // 'hello'</code></pre>
What do <code>toLowerCase()</code> and <code>toUpperCase()</code> do? Give an example.	Case-convert the string (non-locale). Returns <b>new string</b>.<br><br><pre><code>'Hi!'.toLowerCase(); // 'hi!'<br>'Hi!'.toUpperCase(); // 'HI!'</code></pre>
What do <code>toLocaleLowerCase()</code> and <code>toLocaleUpperCase()</code> do? When to use them?	Locale-aware case conversion (e.g. Turkish dotted/dotless i). Pass locale(s) optionally.<br><br><pre><code>'İ'.toLocaleLowerCase('tr'); // 'i'<br>'ß'.toLocaleUpperCase('de-DE'); // 'SS'</code></pre>
What do <code>String.prototype.toString()</code> and <code>valueOf()</code> do?	Return the primitive string value (called automatically in concatenation / coercion). Rarely called directly.<br><br><pre><code>const s = new String('hi');<br>typeof s; // 'object'<br>typeof s.valueOf(); // 'string'</code></pre>
What does <code>String.prototype.toWellFormed()</code> (ES2024) do? Give an example.	Returns a <b>new string</b> with lone surrogates replaced by U+FFFD (�). Pair with <code>isWellFormed()</code>.<br><br><pre><code>'\uD800'.toWellFormed(); // '�'</code></pre>
What does <code>String.prototype.trim()</code> do? Give an example.	Removes whitespace (spaces, tabs, newlines, etc.) from <b>both ends</b>. Returns <b>new string</b>.<br><br><pre><code>'  hi  '.trim(); // 'hi'</code></pre>
What do <code>String.prototype.trimEnd()</code> / <code>trimRight()</code> do?	Remove whitespace from the <b>end</b> only. <code>trimRight</code> is an alias of <code>trimEnd</code>.<br><br><pre><code>'  hi  '.trimEnd(); // '  hi'</code></pre>
What do <code>String.prototype.trimStart()</code> / <code>trimLeft()</code> do?	Remove whitespace from the <b>start</b> only. <code>trimLeft</code> is an alias of <code>trimStart</code>.<br><br><pre><code>'  hi  '.trimStart(); // 'hi  '</code></pre>
How do you iterate a string (code points, spread, <code>for...of</code>)?	Strings are iterable by <b>code point</b> (<code>Symbol.iterator</code>). <code>for...of</code> / spread handle emoji correctly, unlike index loops.<br><br><pre><code>for (const ch of '😀a') console.log(ch); // '😀', 'a'<br>[...'😀a'].length; // 2 ('😀a'.length is 3!)</code></pre>
What does <code>String.fromCharCode()</code> (static) do? What is its limitation?	Builds a string from UTF-16 code <b>units</b>. Cannot directly create astral chars (need surrogate pairs). Use <code>fromCodePoint()</code> instead.<br><br><pre><code>String.fromCharCode(65, 66); // 'AB'</code></pre>
What does <code>String.fromCodePoint()</code> (static) do? Give an example.	Builds a string from Unicode <b>code points</b> (handles emoji/astral chars). Throws on invalid code points.<br><br><pre><code>String.fromCodePoint(128512); // '😀'<br>String.fromCodePoint(65); // 'A'</code></pre>
What does <code>String.raw()</code> (static) do? Give an example.	Raw version of template literals: no escape processing (backslashes kept). Used as a tag, or with <code>{ raw: [...] }</code>.<br><br><pre><code>String.raw`C:\n`; // 'C:\\n' (4 chars, not newline)<br>String.raw({ raw: ['a', 'b'] }, 1); // 'a1b'</code></pre>
What are the deprecated String HTML wrapper methods (e.g. <code>bold()</code>, <code>link()</code>)?	Avoid them: <code>anchor, big, blink, bold, fixed, fontcolor, fontsize, italics, link, small, strike, sub, sup</code> return HTML strings (e.g. <code>'x'.bold()</code> → <code>'&lt;b&gt;x&lt;/b&gt;'</code>). Use DOM / templates instead.
What is the scope difference between <code>var</code>, <code>let</code>, and <code>const</code>? Give an example.	<code>var</code> is <b>function-scoped</b> (visible throughout the function); <code>let</code>/<code>const</code> are <b>block-scoped</b> (only inside <code>{...}</code>).<br><br><pre><code>if (true) { var a = 1; let b = 2; const c = 3; }<br>a; // 1 (leaks out of block)<br>b; // ReferenceError<br>c; // ReferenceError</code></pre>
What is hoisting for <code>var</code>? Give an example.	<code>var</code> declarations are <b>hoisted</b> to the top of their function scope and initialized to <code>undefined</code>. Assignment stays in place.<br><br><pre><code>console.log(x); // undefined (no error)<br>var x = 5;</code></pre>
What is the temporal dead zone (TDZ) for <code>let</code> and <code>const</code>? Give an example.	<code>let</code>/<code>const</code> are hoisted but <b>uninitialized</b>: accessing them before declaration throws <code>ReferenceError</code>.<br><br><pre><code>console.log(y); // ReferenceError: Cannot access 'y' before initialization<br>let y = 5;</code></pre>
What are the declare / redeclare / reassign / initialize rules for <code>var</code> vs <code>let</code> vs <code>const</code>?	<code>var</code>: can redeclare + reassign, no init needed. <code>let</code>: no redeclare in same scope, can reassign, no init needed. <code>const</code>: no redeclare, no reassign, <b>must initialize</b>.<br><br><pre><code>var a = 1; var a = 2; // ok<br>let b = 1; // let b = 2; // SyntaxError<br>const c = 1; // c = 2; // TypeError<br>const d; // SyntaxError: Missing initializer</code></pre>
Does <code>const</code> make a value immutable? Give an example.	No — <code>const</code> only fixes the <b>binding</b>. Objects/arrays declared with <code>const</code> can still be mutated.<br><br><pre><code>const o = { n: 1 }; o.n = 2; // ok<br>o = {}; // TypeError: Assignment to constant variable<br>const a = [1]; a.push(2); // ok: [1, 2]</code></pre>
Why does <code>var</code> in a <code>for</code> loop break closures? How does <code>let</code> fix it?	<code>var</code> is one shared binding, so async callbacks all see the final value. <code>let</code> creates a <b>fresh binding per iteration</b>.<br><br><pre><code>for (var i = 0; i &lt; 3; i++) setTimeout(() =&gt; console.log(i)); // 3, 3, 3<br>for (let j = 0; j &lt; 3; j++) setTimeout(() =&gt; console.log(j)); // 0, 1, 2</code></pre>
How do hoisting rules differ for function declarations vs <code>var</code> vs <code>let</code>?	Function declarations are <b>fully hoisted</b> (callable before definition). <code>var</code> hoists as <code>undefined</code>. <code>let</code>/<code>const</code> sit in the TDZ.<br><br><pre><code>f(); // 'hi' — works<br>function f() { return 'hi'; }<br>g(); // TypeError: g is not a function (var = undefined)<br>var g = () =&gt; 1;</code></pre>
Do top-level <code>var</code> vs <code>let</code>/<code>const</code> attach to <code>globalThis</code> / <code>window</code>?	Top-level <code>var</code> (and function declarations) create properties on the global object; <code>let</code>/<code>const</code>/<code>class</code> go in the declarative global scope instead.<br><br><pre><code>var a = 1; window.a; // 1 (browser)<br>let b = 2; window.b; // undefined</code></pre>
When should you use <code>const</code> vs <code>let</code> vs <code>var</code>?	Default to <code>const</code>; use <code>let</code> only when rebinding is needed (loop counter, accumulator). Avoid <code>var</code> in modern code (function scope + hoisting surprises).<br><br><pre><code>const MAX = 10;<br>let total = 0; for (const n of [1,2]) total += n;</code></pre>
How do you enable strict mode, and where does it apply? What is on by default?	Add <code>'use strict';</code> as the first statement of a script or function (whole-script or function-scoped). ES modules and <code>class</code> bodies are <b>always strict</b>.<br><br><pre><code>'use strict';<br>function f() { 'use strict'; /* only f is strict */ }</code></pre>
What happens in strict mode on assignment to an undeclared variable?	Sloppy mode creates an <b>implicit global</b>; strict mode throws <code>ReferenceError</code>.<br><br><pre><code>'use strict';<br>x = 5; // ReferenceError: x is not defined<br>// sloppy: creates global x (bug-prone)</code></pre>
What happens in strict mode on assignment to a non-writable property, getter-only, or non-extensible object?	Sloppy mode <b>silently fails</b>; strict mode throws <code>TypeError</code>.<br><br><pre><code>'use strict';<br>const o = {}; Object.defineProperty(o, 'x', { value: 1 });<br>o.x = 2; // TypeError<br>Object.preventExtensions(o); o.y = 1; // TypeError</code></pre>
What does strict mode change about <code>delete</code>?	Deleting an <b>undeletable</b> property (non-configurable) or plain variable/function throws <code>TypeError</code> instead of silently failing / returning false.<br><br><pre><code>'use strict';<br>delete Object.prototype; // TypeError<br>var x = 1; delete x; // SyntaxError</code></pre>
What syntax does strict mode forbid: <code>with</code>, octal literals, duplicate params?	<code>with</code> is a <b>SyntaxError</b>. Octal literals (<code>010</code>) and octal escapes (<code>'\1'</code>) are forbidden — use <code>0o10</code> / <code>\x..</code>. Duplicate function parameter names are a SyntaxError.<br><br><pre><code>'use strict';<br>with (o) {} // SyntaxError<br>var n = 010; // SyntaxError (use 0o10)<br>function f(a, a) {} // SyntaxError</code></pre>
What is <code>this</code> inside a plain function call in strict vs sloppy mode?	Sloppy mode boxes <code>this</code> to the global object; strict mode keeps it <code>undefined</code> (fails fast instead of writing to global).<br><br><pre><code>function f() { return this; }<br>f(); // sloppy: window/globalThis, strict: undefined<br>'use strict'; function g() { return this; } g(); // undefined</code></pre>
What does strict mode change about <code>arguments</code>?	No more aliasing: <code>arguments[i]</code> no longer tracks parameter changes. <code>arguments.caller</code> / <code>arguments.callee</code> throw. <code>eval</code>/<code>arguments</code> cannot be used as identifiers.<br><br><pre><code>'use strict';<br>function f(a) { a = 2; return arguments[0]; } f(1); // 1 (sloppy would be 2)<br>var eval = 1; // SyntaxError</code></pre>
What does strict mode change about <code>eval</code> scope?	<code>eval</code> gets its <b>own scope</b>: <code>var</code>/function declarations inside eval do not leak to the enclosing scope (sloppy mode leaks).<br><br><pre><code>'use strict'; eval('var x = 1;');<br>typeof x; // 'undefined' (sloppy: 'number')</code></pre>
What identifiers are reserved in strict mode?	<code>implements, interface, let, package, private, protected, public, static, yield</code> (plus <code>eval</code>/<code>arguments</code> as restricted identifiers) cannot be used as variable/function names.<br><br><pre><code>'use strict';<br>var public = 1; // SyntaxError<br>var yield = 1; // SyntaxError</code></pre>
How does <code>this</code> differ between regular functions and arrow functions?	Regular functions get <b>dynamic</b> <code>this</code> (depends on call site); arrows capture <b>lexical</b> <code>this</code> from the enclosing scope and ignore <code>call/apply/bind</code> for <code>this</code>.<br><br><pre><code>const o = { n: 1, f() { return this.n; }, g: () =&gt; this.n };<br>o.f(); // 1<br>o.g(); // undefined (lexical this, not o)<br>function cb() { setTimeout(() =&gt; this.n, 0); } // arrow keeps this</code></pre>
Do arrow functions have their own <code>arguments</code> object?	No. Arrows share the enclosing <code>arguments</code>; use <b>rest params</b> (<code>...args</code>) instead.<br><br><pre><code>function f() { const g = () =&gt; arguments[0]; return g(); } f(1); // 1 (outer!)<br>const sum = (...ns) =&gt; ns.reduce((a, b) =&gt; a + b, 0);</code></pre>
Can arrow functions be used as constructors with <code>new</code>?	No — arrows throw <code>TypeError</code> with <code>new</code>. They have no <code>prototype</code> and cannot be generators (no <code>yield</code>).<br><br><pre><code>const C = () =&gt; {};<br>new C(); // TypeError: C is not a constructor<br>C.prototype; // undefined</code></pre>
How do hoisting rules differ for function declarations vs arrow functions?	Function declarations are <b>fully hoisted</b> (callable before definition). Arrows assigned to <code>const/let</code> sit in the <b>TDZ</b> until initialized.<br><br><pre><code>f(); // 'hi'<br>function f() { return 'hi'; }<br>g(); // ReferenceError (TDZ)<br>const g = () =&gt; 'hi';</code></pre>
What arrow-function syntax shortcuts exist?	Concise body = <b>implicit return</b>; single param can drop parens; returning an object literal needs parens; multiline needs braces + explicit <code>return</code>.<br><br><pre><code>const double = n =&gt; n * 2;<br>const getO = () =&gt; ({ a: 1 }); // parens required<br>const f = (a, b) =&gt; { return a + b; };</code></pre>
When should you NOT use an arrow function?	As an <b>object/prototype method</b> needing dynamic <code>this</code>, as an <b>event handler</b> using <code>this</code>, or as a <b>constructor</b>. Use shorthand methods or regular functions there.<br><br><pre><code>const o = { n: 1, get: () =&gt; this.n }; o.get(); // undefined — bug!<br>const ok = { n: 1, get() { return this.n; } }; ok.get(); // 1</code></pre>
What does <code>func.call(thisArg, ...args)</code> do? Give an example.	Invokes the function <b>immediately</b> with the given <code>this</code> and comma-separated args.<br><br><pre><code>function greet(g, p) { return `${g}, ${this.name}${p}`; }<br>greet.call({ name: 'Ann' }, 'Hi', '!'); // 'Hi, Ann!'</code></pre>
What does <code>func.apply(thisArg, argsArray)</code> do? How is it different from <code>call</code>?	Invokes the function <b>immediately</b> with the given <code>this</code>, but args passed as an <b>array-like</b>. Same as <code>call</code> + spread.<br><br><pre><code>Math.max.apply(null, [1, 5, 3]); // 5<br>// same as Math.max.call(null, 1, 5, 3) or Math.max(...[1, 5, 3])</code></pre>
What does <code>func.bind(thisArg, ...args)</code> do? Give an example.	Returns a <b>new function</b> with <code>this</code> (and optionally leading args) bound. Does <b>not</b> call it. Enables partial application and stable callbacks.<br><br><pre><code>const f = greet.bind({ name: 'Ann' }, 'Hi');<br>f('!'); // 'Hi, Ann!'<br>setTimeout(obj.method.bind(obj), 100); // keeps this</code></pre>
When would you use <code>call</code> vs <code>apply</code> vs <code>bind</code>? Give a practical example each.	<code>call</code>: borrow a method with known args. <code>apply</code>: forward an unknown/array set of args. <code>bind</code>: fix <code>this</code> for later execution or partially apply.<br><br><pre><code>[].slice.call('abc'); // ['a','b','c'] (borrow)<br>console.log.apply(console, ['a', 'b']); // array args<br>const unsub = emitter.on('e', h.bind(ctx)); // later call</code></pre>
Can <code>call/apply/bind</code> change the <code>this</code> of an arrow function?	No. Arrows ignore the bound <code>thisArg</code> (lexical <code>this</code> wins); only passed args still apply.<br><br><pre><code>const f = () =&gt; this.x;<br>f.call({ x: 1 }); // outer this.x, NOT 1<br>const g = (...a) =&gt; a.join('-'); g.call(null, 1, 2); // '1-2' (args work)</code></pre>
What is an execution context in JavaScript? What are its types?	The environment in which code runs: what variables, scope chain, and <code>this</code> are visible. Types: <b>global</b> (one per program), <b>function</b> (per invocation), <b>module</b> / <b>eval</b> (special cases). Each has a lexical environment + <code>this</code> binding.<br><br><pre><code>// global context → calls f() → new function context → returns → popped</code></pre>
What are the creation vs execution phases of an execution context?	<b>Creation</b>: allocate memory — hoist function declarations, <code>var</code> (= <code>undefined</code>), set up scope chain + <code>this</code>; <code>let/const</code> enter TDZ. <b>Execution</b>: run line by line, assign values.<br><br><pre><code>console.log(a); // undefined (created), not ReferenceError<br>var a = 1;    // assigned in execution phase</code></pre>
What is the call stack? What happens on overflow?	A <b>LIFO</b> stack of execution contexts. Calling pushes, returning pops. JS is single-threaded: one stack. Unbounded recursion throws <code>RangeError: Maximum call stack size exceeded</code>.<br><br><pre><code>function a() { b(); } function b() { return 1; } a(); // push global→a→b, pop back<br>const boom = () =&gt; boom(); boom(); // RangeError</code></pre>
What is the scope chain / lexical environment?	Each context links to its <b>outer</b> lexical environment (where the function was defined, not called). Identifier lookup walks outward to global; this enables closures.<br><br><pre><code>const x = 1;<br>function f() { return x; } // outer = global, finds x<br>function g() { const x = 2; return f(); } g(); // 1 (lexical, not 2)</code></pre>
What is special about the global execution context?	Created first, torn down last. Binds the global object (<code>globalThis</code> / <code>window</code>): top-level <code>var</code>/function declarations become properties, <code>let/const/class</code> do not.<br><br><pre><code>var a = 1; window.a; // 1<br>let b = 2; window.b; // undefined</code></pre>
What are the parts of the JS runtime model around the event loop?	<b>Call stack</b> (runs JS), <b>heap</b> (objects), <b>Web/Node APIs</b> (timers, fetch, DOM), <b>queues</b> (microtask + macrotask/callback), <b>event loop</b> (pushes queued callbacks when the stack is empty).<br><br><pre><code>// setTimeout callback waits in task queue until stack is empty</code></pre>
What is the difference between the microtask queue and the (macro)task / callback queue? Give examples.	Microtasks = high-priority, drain <b>fully</b> after each task: <code>Promise.then/catch/finally</code>, <code>queueMicrotask</code>, <code>MutationObserver</code>. Macrotasks = one per loop turn: <code>setTimeout/Interval</code>, I/O, UI events, <code>setImmediate</code> (Node), <code>MessageChannel</code>.<br><br><pre><code>setTimeout(() =&gt; console.log('macro'), 0);<br>Promise.resolve().then(() =&gt; console.log('micro'));</code></pre>
What is the output order of sync code vs microtasks vs macrotasks?	Sync first, then <b>all</b> microtasks, then the next macrotask (which may queue more microtasks). Starving microtasks blocks rendering/macrotasks.<br><br><pre><code>console.log('1 sync');<br>setTimeout(() =&gt; console.log('2 macro'), 0);<br>Promise.resolve().then(() =&gt; console.log('3 micro'));<br>// 1 sync, 3 micro, 2 macro</code></pre>
What does <code>queueMicrotask()</code> do vs <code>Promise.resolve().then()</code> vs <code>setTimeout(fn, 0)</code>?	<code>queueMicrotask</code> schedules directly on the microtask queue (no promise overhead). <code>Promise.then</code> also microtask but creates a promise. <code>setTimeout 0</code> is a <b>macrotask</b> (min ~0–4ms, throttled in background tabs).<br><br><pre><code>queueMicrotask(() =&gt; console.log('micro'));<br>setTimeout(() =&gt; console.log('macro'), 0); // runs after all micros</code></pre>
What blocks the event loop, and why is <code>setTimeout(fn, 0)</code> not instant?	JS runs to completion: a long sync task <b>blocks</b> rendering + queued callbacks. <code>setTimeout 0</code> still waits for the current stack, all microtasks, earlier macrotasks, and the minimum/clamped delay.<br><br><pre><code>setTimeout(() =&gt; console.log('late'), 0);<br>for (let i = 0; i &lt; 1e9; i++) {} // blocks 'late' for seconds<br>console.log('first'); // first, ..., late</code></pre>
How does the event loop differ in Node.js vs browsers?	Browsers: microtasks, rendering, then next macrotask (<code>rAF</code> before paint). Node adds <code>process.nextTick</code> (runs before promise microtasks) and phases (<code>setImmediate</code> vs <code>setTimeout</code> ordering varies). Same rule holds: sync → microtasks → next task.<br><br><pre><code>process.nextTick(() =&gt; console.log('nextTick'));<br>Promise.resolve().then(() =&gt; console.log('promise')); // nextTick first</code></pre>
What is coercion in JavaScript? Implicit vs explicit?	Automatic (implicit) or manual (explicit) conversion between types using <code>String()</code>, <code>Number()</code>, <code>Boolean()</code>. Operators like <code>+</code>, <code>==</code>, and <code>if()</code> coerce silently — source of most JS weirdness.<br><br><pre><code>String(123); // '123' (explicit)<br>123 + ''; // '123' (implicit)<br>if ('hi') {} // 'hi' → true (implicit boolean)</code></pre>
What is the difference between <code>==</code>, <code>===</code>, and <code>Object.is()</code>?	<code>===</code> = same type + value, no coercion. <code>==</code> coerces first (<code>'1' == 1</code> is true). <code>Object.is()</code> = like <code>===</code> except <code>NaN</code> equals itself and <code>-0</code> differs from <code>+0</code>.<br><br><pre><code>'1' == 1; // true<br>'1' === 1; // false<br>NaN === NaN; // false, Object.is(NaN, NaN); // true<br>0 === -0; // true, Object.is(0, -0); // false</code></pre>
How does the <code>+</code> operator decide between concatenation and addition?	If <b>either</b> operand is a string (after ToPrimitive), it concatenates; otherwise it converts both with <code>Number()</code> and adds. Evaluation is left-to-right.<br><br><pre><code>'5' + 3; // '53'<br>1 + 2 + 'px'; // '3px'<br>'px' + 1 + 2; // 'px12'<br>1 + true; // 2 (no string → numeric)</code></pre>
How do <code>-</code>, <code>*</code>, <code>/</code>, <code>%</code> coerce (vs <code>+</code>)?	They <b>always</b> convert both sides with <code>Number()</code> — no strings. Empty/non-numeric results surprise: <code>''</code> → 0, <code>null</code> → 0, <code>undefined</code> → NaN.<br><br><pre><code>'5' - 3; // 2<br>'5' * '2'; // 10<br>null + 1; // 1 (null → 0)<br>undefined + 1; // NaN (undefined → NaN)</code></pre>
What are all the falsy values in JavaScript?	Exactly 8: <code>false, 0, -0, 0n, '', null, undefined, NaN</code>. Everything else — including <code>[]</code>, <code>{}</code>, and <code>'0'</code> — is truthy.<br><br><pre><code>Boolean('0'); // true (!)<br>Boolean([]); // true<br>Boolean(0n); // false</code></pre>
What is weird about <code>null</code> vs <code>undefined</code> in coercion?	<code>null == undefined</code> (true) but <code>null === undefined</code> (false). Numerically <code>null</code> → 0 but <code>undefined</code> → NaN. And <code>typeof null === 'object'</code> (historic bug).<br><br><pre><code>null == undefined; // true<br>null + 1; // 1<br>undefined + 1; // NaN<br>typeof null; // 'object'</code></pre>
What is weird about <code>NaN</code>? How do you test for it?	<code>NaN</code> means failed number conversion; <code>typeof NaN === 'number'</code> and <code>NaN !== NaN</code>. Global <code>isNaN()</code> coerces first (so <code>isNaN('hi')</code> is true!); prefer <code>Number.isNaN()</code>.<br><br><pre><code>Number('hi'); // NaN<br>isNaN('hi'); // true (coerced — misleading!)<br>Number.isNaN('hi'); // false<br>Number.isNaN(0/0); // true</code></pre>
Why is <code>[] == ![]</code> true? What does it teach?	Both sides coerce to 0: <code>![]</code> → <code>false</code> → 0; <code>[]</code> → <code>''</code> → 0. Yet <code>[]</code> itself is <b>truthy</b>! Lesson: never mix <code>==</code> with truthiness.<br><br><pre><code>Boolean([]); // true<br>[] == false; // true (!!)<br>[] == ![]; // true (!!!)<br>[] === false; // false (use ===)</code></pre>
What do <code>[] + []</code>, <code>[] + {}</code>, and <code>[1,2] + [3,4]</code> evaluate to? Why?	Arrays become strings via <code>join(',')</code>, then <code>+</code> concatenates: <code>[]+[]</code> → <code>''</code>, <code>[]+{}</code> → <code>'[object Object]'</code>, <code>[1,2]+[3,4]</code> → <code>'1,23,4'</code>.<br><br><pre><code>[] + []; // ''<br>[] + {}; // '[object Object]'<br>[1,2] + [3,4]; // '1,23,4'</code></pre>
Why does <code>'b' + 'a' + +'a' + 'a'</code> give <code>'baNaNa'</code>?	<code>+'a'</code> coerces to <code>NaN</code>, which stringifies inside concatenation: <code>'b'+'a'+NaN+'a'</code> → <code>'baNaNa'</code> (lowercase banana!).<br><br><pre><code>+'a'; // NaN<br>'b' + 'a' + +'a' + 'a'; // 'baNaNa'</code></pre>
How do <code>Number()</code> vs <code>parseInt()/parseFloat()</code> differ on messy strings?	<code>Number()</code> requires the <b>whole</b> string to be numeric (else NaN); <code>parseInt/parseFloat</code> parse a <b>prefix</b>. <code>Number('')</code> and <code>Number('  ')</code> are 0 (not NaN!).<br><br><pre><code>Number('12px'); // NaN<br>parseInt('12px'); // 12<br>Number(''); // 0<br>Number(null); // 0, Number(undefined); // NaN</code></pre>
Why does <code>0.1 + 0.2 !== 0.3</code>? How do you compare decimals?	Binary floating point cannot represent 0.1/0.2 exactly (<code>0.1+0.2</code> → <code>0.30000000000000004</code>). Compare with an epsilon or scale to integers.<br><br><pre><code>0.1 + 0.2; // 0.30000000000000004<br>0.1 + 0.2 === 0.3; // false<br>Math.abs(0.1 + 0.2 - 0.3) &lt; Number.EPSILON; // true</code></pre>
When (if ever) is <code>==</code> acceptable? What is the <code>== null</code> idiom?	Rule: default to <code>===</code>. The one accepted <code>==</code> use is <code>x == null</code>, which matches exactly <code>null</code> or <code>undefined</code> (both) — shorter than <code>x === null || x === undefined</code>.<br><br><pre><code>let v;<br>v == null; // true (both null and undefined)<br>v === null; // false (it is undefined)</code></pre>
What is the prototype chain? How does property lookup work?	Every object links to a prototype (or <code>null</code>). Lookup checks <b>own</b> properties first, then walks up via <code>[[Prototype]]</code>. Assignment always writes <b>own</b> (shadowing), never to the prototype.<br><br><pre><code>const p = { a: 1 }; const o = Object.create(p);<br>o.a; // 1 (inherited)<br>o.a = 2; // own property, p.a still 1</code></pre>
What is the difference between <code>__proto__</code>, <code>prototype</code>, and <code>Object.getPrototypeOf()</code>?	<code>__proto__</code> = legacy accessor for an instance's prototype. <code>Fn.prototype</code> = object assigned as prototype to instances created by <code>new Fn()</code>. Use <code>Object.getPrototypeOf(o)</code> / <code>Object.create(proto)</code> instead of <code>__proto__</code>.<br><br><pre><code>function F() {}<br>const o = new F();<br>Object.getPrototypeOf(o) === F.prototype; // true<br>o.__proto__ === F.prototype; // true (legacy)</code></pre>
How does <code>Object.create(proto)</code> implement inheritance? Give an example.	Creates a new object with <code>[[Prototype]]</code> set to <code>proto</code> — pure prototypal inheritance, no constructor involved.<br><br><pre><code>const animal = { speak() { return 'sound'; } };<br>const dog = Object.create(animal);<br>dog.speak(); // 'sound' (inherited)</code></pre>
What exactly does the <code>new</code> operator do?	1. create fresh object 2. set its prototype to <code>Fn.prototype</code> 3. call <code>Fn</code> with <code>this</code> = new object 4. return <code>this</code> unless the constructor returns its own object.<br><br><pre><code>function User(n) { this.name = n; }<br>User.prototype.hi = function () { return this.name; };<br>const u = new User('Ann'); u.hi(); // 'Ann'</code></pre>
How do you check own vs inherited properties (<code>in</code> vs <code>hasOwnProperty</code>)?	<code>'k' in o</code> walks the chain; <code>o.hasOwnProperty('k')</code> (or <code>Object.hasOwn(o,'k')</code>) checks own only. <code>for...in</code> includes inherited enumerable props — prefer <code>Object.keys()</code> for own.<br><br><pre><code>'toString' in {}; // true (inherited)<br>({}).hasOwnProperty('toString'); // false<br>Object.keys({ a: 1 }); // ['a'] (own only)</code></pre>
Why put methods on the prototype instead of in the constructor?	Prototype methods are <b>shared</b> (one function for all instances); constructor-assigned methods are <b>copied per instance</b> (more memory). Define state in the constructor, behavior on the prototype.<br><br><pre><code>function C() { this.m = () =&gt; 1; } // new fn per instance — wasteful<br>C.prototype.m = function () { return 1; }; // shared — preferred</code></pre>
What does <code>class</code> add over constructor functions?	Mostly syntax sugar over prototypes: <code>constructor</code> runs on <code>new</code>, methods live on <code>C.prototype</code>, <code>extends</code> wires the chain. Classes are <b>not hoisted</b> (TDZ) and always <b>strict</b>.<br><br><pre><code>class A { constructor() { this.x = 1; } m() { return this.x; } }<br>typeof A; // 'function'<br>A.prototype.m; // function (shared)</code></pre>
How do <code>extends</code> and <code>super</code> work in classes?	<code>class B extends A</code> sets <code>B.prototype.[[Prototype]]</code> to <code>A.prototype</code>. In a derived constructor you must call <code>super(...args)</code> <b>before</b> touching <code>this</code>; <code>super.m()</code> calls the parent method.<br><br><pre><code>class A { hi() { return 'A'; } }<br>class B extends A { constructor() { super(); } hi() { return super.hi() + 'B'; } }<br>new B().hi(); // 'AB'</code></pre>
What are <code>static</code> members and <code>#private</code> fields in classes?	<code>static</code> lives on the <b>class itself</b> (often factories/utils), not instances. <code>#name</code> fields/methods are <b>truly private</b> (inaccessible outside, unlike <code>_convention</code>).<br><br><pre><code>class C { static make() { return new C(); } #s = 1; get() { return this.#s; } }<br>C.make(); // ok<br>new C().s; // undefined (#s hidden)</code></pre>
How does <code>instanceof</code> work? What are its pitfalls?	Checks whether <code>C.prototype</code> appears anywhere in the object's chain. Breaks across realms (iframes) and with <code>Symbol.hasInstance</code> overrides; primitives need boxing (<code>'x' instanceof String</code> is false).<br><br><pre><code>[] instanceof Array; // true<br>[] instanceof Object; // true (chain: Array → Object)<br>'x' instanceof String; // false</code></pre>
What is the top of the prototype chain? What is <code>Object.create(null)</code> for?	Chain ends at <code>null</code>: <code>o → ... → Object.prototype → null</code>. <code>Object.create(null)</code> makes a dict with <b>no</b> prototype (no <code>toString</code>, safe from prototype pollution, good for maps).<br><br><pre><code>({}).toString; // function (from Object.prototype)<br>const d = Object.create(null); d.toString; // undefined</code></pre>
Should you favor inheritance or composition in JS?	Prefer <b>composition</b> (combine small objects/functions) over deep <code>extends</code> chains — shallower hierarchies avoid fragile-base-class bugs. Use <code>extends</code> for true is-a relations, mixins/<code>Object.assign</code> otherwise.<br><br><pre><code>const withLog = (o) =&gt; ({ ...o, log() { console.log(this); } });<br>const user = withLog({ name: 'Ann' }); // composition</code></pre>
